Tổng quan bài Lab (Mission Overview)

Mục tiêu của bài lab là xây dựng một hệ thống Support-Ticket Orchestration Agent chuẩn production bằng framework LangGraph. Khác với các chuỗi xử lý tuyến tính thông thường (LCEL linear chains vốn không thể quay đầu hay xử lý lỗi lặp), hệ thống sở hữu khả năng quản lý trạng thái động (dynamic state management), phân loại ý định qua LLM structured output, tự phục hồi lỗi qua vòng lặp thử lại có giới hạn (bounded retry loop), tích hợp phê duyệt từ con người (HITL approval) trước khi thực hiện tác vụ rủi ro, và lưu vết trạng thái bền vững (durable persistence).

2

Lý thuyết nền tảng (Core Theoretical Concepts)

🔄 Agentic DAG vs Cyclic Graphs (DCG)

Chuỗi LCEL truyền thống hoạt động dưới dạng Directed Acyclic Graph (DAG) không chu trình, khiến việc thực hiện retry khi API lỗi hoặc lặp lại hội thoại trở nên bất khả thi.

LangGraph mô hình hóa quy trình thành State Machine dạng đồ thị có chu trình (Cyclic Graph), cho phép luồng điều khiển quay vòng (loop back) linh hoạt.

📦 State Management & Reducers

State trong LangGraph là một TypedDict. Khi một Node trả về dữ liệu, LangGraph cập nhật trạng thái thông qua Reducers:

  • Overwrite (Ghi đè): route, attempt, final_answer chỉ lưu giá trị mới nhất.
  • Append-only (Ghi nối tiếp): Annotated[list, operator.add] cho events, tool_results, errors để bảo toàn lịch sử audit.

🎯 LLM Structured Output & Intent Routing

Node classify_node bắt buộc sử dụng .with_structured_output(ClassificationResult) từ LLM thay vì keyword regex, đảm bảo phân loại chuẩn xác theo thứ tự ưu tiên: risky > tool > missing_info > error > simple.

⚖️ LLM-as-a-Judge Evaluation

Trong evaluate_node, mô hình LLM đóng vai trò thẩm phán khách quan (Judge) để phân tích kết quả trả về từ công cụ: đánh giá xem output có chứa thông điệp lỗi hoặc cần retry hay đã thành công.

🛑 Human-In-The-Loop (HITL) Authorization

Đối với các hành động rủi ro cao (hoàn tiền, xóa tài khoản), agent không được tự ý thực thi. Hệ thống chuyển qua node approval để lấy xác nhận. Nếu từ chối, luồng điều hướng sang clarify thay vì thực thi tác vụ phá hủy.

💾 Checkpointing & Time-Travel

State được lưu sau mỗi superstep vào SqliteSaver (hỗ trợ WAL mode). Điều này đảm bảo: khôi phục sau crash (crash-resilience), quản lý đa luồng qua thread_id, và xem lại lịch sử trạng thái (time-travel replay).

Phân tích các tình huống lỗi & Cơ chế an toàn

1. Bounded Retry Loop chống tràn tài nguyên

Khi API bên ngoài gặp lỗi tạm thời (timeout, 503), hệ thống chuyển sang node retry và tăng attempt. Hàm điều hướng route_after_retry đảm bảo attempt < max_attempts. Khi vượt ngưỡng, hệ thống tự động chuyển sang dead_letter thay vì loop vô tận.

2. Human-In-The-Loop bảo vệ hành vi rủi ro

Các hành động thay đổi dữ liệu người dùng (hoàn tiền, xóa tài khoản) luôn phải qua kiểm duyệt. Khi người duyệt từ chối (approved=False), luồng chuyển ngay sang clarify để bảo vệ an toàn cho hệ thống.
